# Админка QURAL-SAIMAN

Next.js 14 (App Router) + Supabase. Управление каталогом: инструменты, категории, ДГУ, акция, фото, настройки сайта.

## Запуск

База должна быть готова — см. `db/README.md` в основном проекте (schema.sql + seed.sql + бакет `tools` + запись в `admins`).

```bash
npm install
cp .env.example .env.local
```

Открыть `.env.local` и подставить два значения из Supabase:

| Переменная | Где взять |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project Settings → Data API → API URL, **без** `/rest/v1/` |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Project Settings → API Keys → Publishable key (`sb_publishable_…`) |

```bash
npm run dev
```

Открыть http://localhost:3000 — редирект на `/login`, войти под email и паролем из Authentication.

## Деплой на Vercel

1. Залить папку в репозиторий (можно как отдельный репо или подпапку с Root Directory = `nextjs-admin`)
2. [vercel.com](https://vercel.com) → Add New Project → выбрать репозиторий
3. Environment Variables — добавить те же две переменные
4. Deploy

Домен вида `admin-qural-saiman.vercel.app`. Позже можно повесить свой, например `admin.qural-saiman.kz`.

## Структура

```
app/
  actions.js          все мутации (server actions), проверка сессии + RLS
  login/              вход
  tools/              инструменты: таблица, фильтры, порядок, форма
  categories/         семейства и категории, drag-сортировка, выбор иконки
  dgu/                генераторы
  pricing/            акция 5+1, правила расчёта (вышки, леса)
  media/              фото: массовая загрузка, «нужны фото»
  settings/           контакты, соцсети, SEO, смена пароля
components/           Shell, Sidebar, Drawer, Toast, Toggle, IconPicker, PhotoField
lib/
  supabase/           клиенты для браузера, сервера и middleware
  data.js             чтение данных для страниц
  format.js           формат цен, склонения, ссылки на фото
middleware.js         защита роутов, обновление сессии
```

## Как это работает

**Доступ.** `middleware.js` не пускает дальше `/login` без сессии. Запись в базу разрешена только тем, кто есть в таблице `admins` — проверка на стороне Postgres (RLS), не в коде. Даже с publishable-ключом изменить каталог нельзя.

**Мутации.** Все через server actions в `app/actions.js` — данные не уходят в браузер, после сохранения `revalidatePath` перерисовывает страницу.

**Фото.** Загружаются напрямую в бакет `tools` с клиента, имя файла = артикул позиции. Путь пишется в `photo_path`. Замена файла с тем же именем перезаписывает старый (`upsert`).

**Порядок.** `sort` считается внутри категории. В режиме «Порядок» нужно сначала выбрать категорию — иначе перетаскивать нечего.

**KZ.** Поля `*_kz` есть в формах, интерфейс админки только на русском. Пустое KZ-поле означает «показывать русское».

## Чего здесь нет

- **Наличия.** Остатки ведутся в 1С и на сайт не выводятся.
- **Заявок.** Клиент пишет в WhatsApp, переписка живёт там.
- **Процентных скидок.** Единственная акция — 5+1, только бензо- и электроинструмент.

## Следующий шаг

Сайт пока берёт каталог из `tools-data.js`. Чтобы он читал базу, нужен один публичный endpoint (`/api/catalog`), который отдаёт JSON в том же формате — тогда сайт меняется на одну строку и продолжает работать как есть.
